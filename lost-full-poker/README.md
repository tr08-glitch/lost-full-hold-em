# ロストフルホールデム 開発資料

『混沌』と同じ進め方(仕様をドキュメント化し、実装はご自身で行う・壁打みベース)を想定した初期資料一式です。

## 中身
```
lost-full-poker/
├── README.md              このファイル
├── docs/
│   ├── rules.md            ゲーム全体ルール(確定分)
│   └── screens/
│       ├── title.md        タイトル画面 仕様
│       ├── room-create.md  ルーム作成画面 仕様
│       ├── room-join.md    ルーム参加画面 仕様
│       ├── table.md        対戦卓画面 仕様
│       └── exchange.md     身体パーツ換金画面 仕様
├── server/                 実際のオンライン対戦サーバー(Node.js + Colyseus)
└── mockups/
    ├── index.html           **本体。タイトル〜対戦卓までが1画面で完結するSPA。Renderのルートアクセスでそのまま開く**
    └── exchange.html        身体パーツ換金画面の単体参考ページ(index.html内のドロワーと同内容)
```

## 現在の状態(重要)
以前はタイトル・ルーム作成・ルーム参加・対戦卓がそれぞれ別のHTMLファイルで、画面が変わるたびにページ遷移していました。
この方式だと、ページ遷移のたびにサーバーとの接続が一度切れて繋ぎ直す必要があり、Renderの無料プランでは
「切断の検知に20秒以上かかる」という特性と組み合わさって再接続が安定しない、という問題がありました。

そこで **`index.html` 1つに統合し、画面切り替えは全てJavaScript側(`showScreen()`によるdiv表示切り替え)で行う
(ページ遷移なし)** 構成に作り直しました。ルーム作成・参加時に一度だけサーバーへ接続し、その後はゲームが
終わるまで同じ接続(`room`変数)を保持し続けます。これにより、以前悩まされていた再接続まわりの不安定さが
そもそも発生しない作りになっています(『混沌』も同じ1画面完結の作り方でオンライン対戦を実現しています)。

- `docs/screens/` の各仕様書(title.md / room-create.md / room-join.md / table.md)は、画面ごとの要素・レイアウトの
  仕様としては引き続き有効です(`index.html`内の各`.app-screen`がこれに対応します)。ファイル自体は統合されています
- サーバー側(`server/`)の実装内容は`server/CLIENT_PROTOCOL.md`を参照してください
- `index.html`冒頭の`SERVER_URL`定数を、実際にデプロイしたサーバーの`wss://...`アドレスに書き換える必要があります

## 混沌と同じ進め方について
これまで混沌では、以下の流れで進めてきました。

1. 画面ごとに手書きラフを見せてもらい、要素・配置をヒアリング
2. 仕様として文章化(このリポジトリのdocs/screens/のようなもの)
3. ゲームロジック(役の判定、ターン進行など)はルールとして先に文章で固める
4. 実装自体はユーザー自身が進める。Claudeとは壁打ち・相談ベースで、詰まった部分や新しい画面の仕様を一緒に決めていく
5. オンライン対戦部分(ルームの同期など)は、サーバー/DBまわりのコード一式をClaudeが作成し、ユーザーがデプロイする形を想定(混沌・ターン制城ゲームと同じ方針)。技術構成はWebブラウザ向けで、Node.js + Colyseus(またはSocket.io)を想定

ロストフルホールデムも同じ流れで進めるのがやりやすいと思います。今回はまず「タイトル画面」「ルーム作成画面」「ルーム参加画面」の3つと、これまで固まった全ルールをドキュメント化しました。
